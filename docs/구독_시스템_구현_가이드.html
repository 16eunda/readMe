🗄️ Subscription 테이블 구조

필드타입설명
idLongPK
userUserEntity로그인 유저 (게스트면 null)
deviceIdString게스트 기기 ID (로그인이면 null)
platformIOS / ANDROID결제 플랫폼
planTypemonthly / yearly구독 플랜
startedAtLocalDateTime구독 시작일
expiresAtLocalDateTime⭐ 핵심: 만료일. 이게 지나면 isPremium = false
statusACTIVE/EXPIRED/CANCELLED구독 상태
autoRenewBoolean자동 갱신 여부
receiptTEXTiOS 영수증 (매우 긴 문자열)
purchaseTokenStringAndroid 구매 토큰
originalTransactionIdStringiOS 최초 구매 ID (갱신 묶음용)
createdAt / updatedAtLocalDateTime레코드 생성/변경 시각
expiresAt + status 동시 체크가 핵심
status == ACTIVE && expiresAt.isAfter(now())
→ status만 보면 취소됐는데도 프리미엄으로 보일 수 있음. 만료일도 같이 체크해야 정확함.

🔍 isPremium 판단 로직

앱에서 API 호출: GET /subscriptions/status
↓
Controller → Service.isPremium(user, deviceId) 호출
↓
로그인 유저? → userId로 조회 / 게스트? → deviceId로 조회
↓
DB에서 status=ACTIVE 구독 조회
↓
expiresAt > 현재시각? → true / 아니면 false
↓
{ "isPremium": true | false } 응답
// SubscriptionService.java
public boolean isPremium(UserEntity user, String deviceId) {
    Optional<Subscription> sub = (user != null)
        ? repo.findTopByUserAndStatusOrderByExpiresAtDesc(user, ACTIVE)
        : repo.findTopByDeviceIdAndStatusOrderByExpiresAtDesc(deviceId, ACTIVE);

    return sub.map(s -> s.getExpiresAt().isAfter(LocalDateTime.now()))
              .orElse(false);
}

🔌 API 목록

GET /subscriptions/status
구독 상태 확인. 앱 시작 / 로그인 시 자동 호출됨. 응답: { "isPremium": true }
POST /subscriptions/subscribe
결제 후 구독 활성화. 앱스토어/구글플레이 영수증을 받아 검증 후 DB 저장
POST /subscriptions/webhook/apple
애플이 자동으로 보내는 알림 수신. 갱신/취소/만료 이벤트 → DB 업데이트
POST /subscriptions/webhook/google
구글 Pub/Sub 알림 수신. notificationType으로 갱신(1)/취소(3)/만료(13) 분기
POST /subscriptions/test-activate
⚠️ 테스트용. 결제 없이 1년짜리 구독 DB에 직접 생성. 배포 전 삭제

🍎 애플(iOS) 결제 + 검증 흐름

① 유저가 앱 내에서 구독 버튼 클릭 (react-native-iap)
↓
② 앱스토어 결제 완료 → 영수증(receipt-data) 발급
↓
③ 앱이 영수증을 백엔드로 전송: POST /subscriptions/subscribe
↓
④ 백엔드 → 애플 서버에 영수증 검증 요청
POST https://buy.itunes.apple.com/verifyReceipt
Body: {
  "receipt-data": "영수증 문자열",
  "password": "App Store Connect 공유 비밀키"
}

응답:
  status: 0     → 유효한 영수증 ✅
  status: 21007 → 샌드박스 영수증 (샌드박스 URL로 재시도)
  그 외         → 유효하지 않음 ❌
⑤ 검증 성공 → DB에 구독 저장 (status=ACTIVE, expiresAt 설정)
↓ (이후 자동 갱신/취소 시)
⑥ 앱스토어가 등록된 URL로 자동 POST (webhook)
↓
⑦ 백엔드가 이벤트 수신 → DB status/expiresAt 업데이트
필요한 설정:
App Store Connect → 앱 내 구입 → 공유 비밀키 발급
App Store Connect → 앱 정보 → App Store Server Notifications URL 등록

🤖 구글(Android) 결제 + 검증 흐름

① 유저가 구글플레이에서 결제 완료 → purchaseToken 발급
↓
② 앱이 purchaseToken을 백엔드로 전송
↓
③ 백엔드 → 구글 서버에 토큰 검증 요청
GET https://androidpublisher.googleapis.com/androidpublisher/v3/
    applications/{packageName}/purchases/subscriptions/{subscriptionId}/tokens/{token}

응답:
  paymentState: 1 → 결제 완료 ✅
  paymentState: 0 → 결제 대기 중
  paymentState: 2 → 무료 체험
④ 검증 성공 → DB에 구독 저장
↓ (이후 갱신/취소 시)
⑤ Google Cloud Pub/Sub → 백엔드 URL로 자동 전송
↓
notificationType: 1=갱신 / 3=취소 / 13=만료
↓
⑥ DB status/expiresAt 업데이트
필요한 설정:
Google Play Console → 서비스 계정 생성 → JSON 키 파일 발급
Google Cloud Console → Pub/Sub 토픽 생성 → 백엔드 URL 등록

📱 프론트 isPremium 흐름

앱 시작
  → UserContext 초기화
  → AsyncStorage에서 로그인 정보 로드
  → checkSubscription() 호출
      → GET /subscriptions/status
      → isPremium 상태 저장
      → AsyncStorage에 캐시 (오프라인 대비)

로그인 시
  → login() 호출 → checkSubscription() 자동 호출

로그아웃 시
  → logout() 호출
  → isPremium = false
  → AsyncStorage 'isPremium' 키 삭제

프리미엄 기능 접근 시
  → isPremium 체크
  → false면 /subscription 화면으로 이동
  → true면 기능 사용 가능
