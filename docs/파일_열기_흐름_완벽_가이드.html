② 외부 "다른 앱으로 열기" (Open With)

안드로이드에서 URL이 어떻게 전달되나?

파일 탐색기에서 파일을 선택하면 시스템이 앱을 실행하면서 딥링크 URL을 전달합니다.

// 파일 탐색기 → readMe 앱 선택 시 전달되는 URL
myreaderapp2://media/external/file/1000020537

// 왜 myreaderapp2:// 로 오나?
// → app.json의 "scheme": "myreaderapp2" 설정 때문
// 안드로이드는 content://media/... URI를 앱 스킴으로 변환해서 전달
//   content://media/external/file/1000020537
//       ↓  앱스킴으로 변환
// myreaderapp2://media/external/file/1000020537
ℹ️
숫자 ID란? 1000020537은 파일명이 아니라 안드로이드 미디어 스토어의 파일 고유 ID입니다. 이 URI는 직접 읽을 수 없고 반드시 앱 전용 저장소로 복사해야 합니다.

파일 경로 종류 정리

경로 종류예시특징
content:// content://media/external/file/1000020537 안드로이드 미디어 스토어. 직접 읽기 불가, 반드시 복사 필요
캐시 디렉토리 file:///data/.../cache/파일명.epub 임시 저장. OS가 언제든 삭제 가능
documentDirectory file:///data/.../files/파일명.epub 영구 저장. 앱 삭제 전까지 유지
서버 DB uri 필드 file:///data/.../files/파일명.epub documentDirectory 경로를 DB에 저장해둠
⚠️
앱 재설치 시 경로 변경 문제 앱을 재설치하면 documentDirectory 경로의 일부(UUID 부분)가 변경될 수 있습니다. 이 경우 DB에 저장된 uri로 파일을 찾지 못해 ENOENT 에러가 발생합니다. readWithFallback() 함수로 파일명만으로 새 경로를 재시도해 해결합니다.

자주 발생하는 문제와 원인

문제
"Unmatched Route" 에러 화면
원인
외부 딥링크(myreaderapp2://media/...)가 라우트로 잘못 해석됨
해결
+not-found.tsx에서 가로채서 content:// 복원 후 처리
문제
파일 열기 시 ENOENT 에러
원인
앱 재설치 후 documentDirectory 경로 UUID가 변경됨
해결
readWithFallback()으로 파일명 기반 새 경로 재시도
문제
한글 txt 파일이 깨짐
원인
CP949/EUC-KR 인코딩 파일을 UTF-8로 읽음
해결
decodeTextSafe()로 BOM 체크 후 인코딩 자동 감지
문제
이어읽기가 안 됨 (처음부터 시작)
원인
초기화 타이밍에 progress=0으로 덮어쓰기됨
해결
initialProgressRef로 0 덮어쓰기 방지 처리
문제
강제종료 시 진행도 저장 안 됨
원인
스와이프 킬 시 unmount가 실행되지 않음
해결
AppState 'background' 이벤트 감지 시 즉시 저장
