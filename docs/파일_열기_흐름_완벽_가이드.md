# 파일 열기 흐름 완벽 가이드

> **readMe 앱**에서 파일이 어떤 과정을 거쳐 읽히는지를 단계별로 설명합니다.

---

## 파일을 앱에 추가하는 방법 2가지

| 방법 | 진입점 | 설명 |
|------|--------|------|
| **① 앱 내 + 버튼** | `index.tsx` → `pickFile()` | 앱 안에서 직접 파일 선택 |
| **② 외부 앱에서 "Open With"** | `_layout.tsx` or `+not-found.tsx` | 파일 탐색기/다른 앱에서 공유 |

---

## 방법 ① : 앱 내 + 버튼으로 파일 추가

```
사용자가 + 버튼 클릭
        │
        ▼
pickFile() 실행
        │
        ▼
DocumentPicker.getDocumentAsync()
  → 시스템 파일 선택창 열림 (.txt, .epub 만 필터)
  → 사용자가 파일 선택
  → copyToCacheDirectory: true → 캐시에 임시 복사
        │
        ▼
서버에 중복 체크 API 호출
GET /files/check?title=파일명&path=현재폴더
        │
        ├─ 중복 있음 → DuplicateConfirmModal 표시
        │              사용자가 "덮어쓰기" or "취소" 선택
        │
        └─ 중복 없음 → addFileToSystem() 실행
                │
                ▼
        FileSystem.copyAsync()
          캐시(임시) → 앱 전용 documentDirectory로 영구 복사
          경로: file:///data/.../files/파일명.epub
                │
                ▼
        미리보기 텍스트 추출
          .epub → JSZip으로 압축 해제 → OPF → 첫 번째 챕터 HTML → 텍스트 50자
          .txt  → Base64로 읽기 → 인코딩 자동 감지 (UTF-16, UTF-8, CP949...) → 50자
                │
                ▼
        서버에 파일 정보 저장
        POST /files
          { title, preview, date, rating, uri(로컬경로), path(폴더), deviceId }
                │
                ▼
        서버에서 id 부여된 파일 객체 반환 (saved)
                │
                ▼
        React Query 캐시 즉시 업데이트 (Optimistic Update)
        → 화면에 파일 카드 즉시 표시
```

## 방법 ② : 외부에서 "다른 앱으로 열기"

### 안드로이드 동작 원리

안드로이드에서 파일 탐색기에서 파일을 선택하면, 시스템이 앱을 실행하면서 **딥링크 URL**을 전달합니다.

```
파일 탐색기에서 .epub/.txt 파일 선택
        │
        ▼
"어떤 앱으로 열까요?" 선택창
        │
        ▼
readMe 앱 선택
        │
        ▼
시스템이 앱에 URL 전달
형식: myreaderapp2://media/external/file/1000020537
                     ↑앱스킴       ↑ content:// 경로 (숫자는 파일 ID)
```

왜 `myreaderapp2://`로 오나? → `app.json`의 `"scheme": "myreaderapp2"` 설정 때문.
안드로이드는 `content://media/...` URI를 앱 스킴으로 변환해서 전달합니다.

---

### 앱 실행 상태에 따른 처리 분기

#### Case A: 앱이 완전히 꺼진 상태 (Cold Start)

```
시스템 → myreaderapp2://media/... 딥링크 전달
        │
        ▼
Expo Router가 URL을 라우트로 해석
"/media/external/file/1000020537" 라는 라우트는 없음!
        │
        ▼
+not-found.tsx 실행 (Unmatched Route 처리)
        │
        ▼
Linking.getInitialURL() 로 원본 URL 다시 읽기
        │
        ▼
URL 패턴 분석
  myreaderapp2://media/... 감지
  → "media/" 로 시작하면 파일 URI로 판단
  → content://media/external/file/1000020537 로 복원
        │
        ▼
FileSystem.copyAsync()
  content://... → 앱 캐시 디렉토리로 복사
  (안드로이드 content URI는 직접 읽기 불가, 반드시 복사 필요)
        │
        ▼
setIncomingFile({ uri: 캐시경로, name: "1000020537.epub" })
  → UserContext에 저장
        │
        ▼
router.replace('/(tabs)') → 홈 화면으로 이동
        │
        ▼
index.tsx의 useEffect가 incomingFile 감지
        │
        └─ (아래 "공통 처리 단계"로 이어짐)
```

#### Case B: 앱이 백그라운드에 있는 상태 (Warm Start)

```
시스템 → URL 이벤트 전달
        │
        ▼
_layout.tsx의 Linking.addEventListener 콜백 실행
        │
        ▼
processIncomingUrl() 함수 실행
  myreaderapp2:// → content:// 복원
        │
        ▼
FileSystem.copyAsync() → 캐시 복사
        │
        ▼
setIncomingFile() → UserContext에 저장
router.replace('/(tabs)')
        │
        └─ (아래 "공통 처리 단계"로 이어짐)
```

### 공통 처리 단계 (index.tsx)

```
incomingFile이 UserContext에 세팅됨
        │
        ▼
index.tsx의 useEffect([incomingFile]) 트리거
        │
        ▼
setIncomingFile(null) → 중복 처리 방지
        │
        ▼
서버에 중복 체크
GET /files/check?title=파일명&path=root
        │
        ├─ 중복 있음 → Alert 표시
        │   ┌─ "그냥 열기" → 기존 파일 찾아서 reader로 이동
        │   └─ "새로 추가" → addFileToSystem() 실행 후 reader로 이동
        │
        └─ 중복 없음 → addFileToSystem() 실행 후 reader로 이동
                │
                ▼
        (방법 ①과 동일한 addFileToSystem 흐름)
```

## addFileToSystem() 내부 상세

```
file: { uri: 로컬/캐시 경로, name: "파일명.epub" }
        │
        ▼
① 영구 저장소로 복사
   from: file:///cache/파일명.epub  (임시)
   to:   file:///data/.../files/파일명.epub  (영구, documentDirectory)
        │
        ▼
② 미리보기 추출 (50자)
   .epub:
     JSZip으로 zip 파일 열기
     → META-INF/container.xml 읽기 → OPF 파일 경로 확인
     → OPF에서 spine(읽기 순서) 첫 번째 챕터 경로 확인
     → 해당 HTML 파일 읽기 → html-to-text로 텍스트 변환 → 50자
   .txt:
     Base64로 파일 전체 읽기
     → Buffer로 변환
     → BOM 체크 (UTF-16 LE/BE, UTF-8)
     → 인코딩 순서대로 시도: CP949 → UTF-8 → EUC-KR → UTF-16...
     → 한글 문자 있고 깨진 문자 1% 미만인 첫 번째 성공 인코딩 사용
     → 50자
        │
        ▼
③ 서버 DB에 저장
   POST /files
   body: {
     title: "파일명.epub",
     preview: "앞의 50자...",
     date: "2026-05-19T09:43:00.000Z",
     rating: 0,
     uri: "file:///data/.../files/파일명.epub",  ← 영구 경로
     path: "root",  ← 폴더 위치
     deviceId: "xxxx-xxxx"
   }
        │
        ▼
④ 서버가 id 포함된 파일 객체 반환
   { id: 15, title: ..., uri: ..., ... }
        │
        ▼
⑤ React Query 캐시 즉시 업데이트
   화면에 새 파일 카드 즉시 표시 (API 재조회 없이)
   백그라운드에서 서버와 동기화
        │
        ▼
⑥ saved 객체 반환 → router.push('/reader')
```

## reader.tsx에서 파일 읽기

```
router.push('/reader', { fileId, uri, name })
        │
        ▼
reader.tsx 진입
        │
        ▼
① 서버에서 저장된 진행도/위치 로드
   GET /files/{fileId}
   → progress (0.0~1.0), epubCfi (epub 위치 문자열) 반환
        │
        ▼
② 파일 형식 판단
   name.endsWith('.epub') → EPUB 모드
   그 외 → TXT 모드
        │
   ┌────┴────┐
   │         │
  EPUB       TXT
   │         │
   ▼         ▼
WebView    FlatList 가상화
(epub.js)  (문단 배열 렌더링)
   │         │
   └────┬────┘
        │
        ▼
③ 이어읽기 처리
   .epub → epubCfi로 해당 위치로 이동
   .txt  → progress × 전체높이 = scrollY로 스크롤
        │
        ▼
④ 읽는 중 진행도 추적
   .epub → epub.js의 relocated 이벤트 → WebView 메시지로 수신
   .txt  → onScroll 이벤트 → scrollY / (contentHeight - viewHeight)
        │
        ▼
⑤ 진행도 저장 (2가지 시점)
   - 뒤로가기/화면 닫기 → useEffect cleanup(unmount) 시 즉시 저장
   - 강제종료(스와이프 킬) → AppState 'background' 감지 시 즉시 저장
   PATCH /files/{fileId}/progress
   body: { progress: 0.73, epubCfi: "epubcfi(/6/4...)", recordReadLog: true }
```

## 파일 경로 정리

| 경로 종류 | 예시 | 특징 |
|-----------|------|------|
| **content://** | `content://media/external/file/1000020537` | 안드로이드 미디어 스토어. 직접 읽기 불가, 복사 필요 |
| **캐시 디렉토리** | `file:///data/.../cache/파일명.epub` | 임시 저장, OS가 삭제할 수 있음 |
| **documentDirectory** | `file:///data/.../files/파일명.epub` | 영구 저장, 앱 삭제 전까지 유지 |
| **서버 DB uri 필드** | `file:///data/.../files/파일명.epub` | documentDirectory 경로를 DB에 저장 |

---

## 자주 발생하는 문제와 원인

| 문제 | 원인 | 해결 |
|------|------|------|
| "Unmatched Route" 에러 | 외부 딥링크가 라우트로 잘못 해석됨 | `+not-found.tsx`에서 가로채서 처리 |
| 파일 ENOENT 에러 | documentDirectory 경로가 앱 재설치 후 변경됨 | `readWithFallback()`으로 새 경로 재시도 |
| 한글 txt 깨짐 | CP949/EUC-KR 인코딩 파일을 UTF-8로 읽음 | `decodeTextSafe()`로 인코딩 자동 감지 |
| 이어읽기 안 됨 | progress가 0으로 덮어쓰기됨 | `initialProgressRef`로 0 덮어쓰기 방지 |
